# 发给服务器编码 AI 的提示词

以下全文可直接发给服务器上的 AI。请同时让它能读取同目录 `design.md` 和 `implementation_plan.md`。

---

请在当前服务器现有球形机器人导航仓库中实施本交接包。目标有两个：

1. 复用已知障碍地图导航和现有低层执行链，采集可审计、可用于后续学习的仿真轨迹。
2. 实现左右 RGB 分别做米制单目深度，再融合地图、经典规划和现有控制的视觉 baseline。

先完整阅读同目录 `design.md` 和 `implementation_plan.md`。它们是需求，不是已经存在的实现；路径和 CLI 为候选接口，先在当前仓库做实际映射。你需要真正修改代码和运行验证，不能只输出计划。

### 第一步：确认实际工程

读取仓库规则、README、当前 Git 状态、已知成功 Oracle 入口、相机/状态/动作/接触/writer/audit 模块和模型依赖。生成 `reports/navigation_baseline/environment_inventory.md`，记录真实路径、提交、未提交改动、环境和现存失败。不要覆盖用户已有改动、权重、历史数据和日志，不批量升级原仿真环境。

本地旧材料有 DA3 Metric 左右独立推理代码，也有 Hybrid A*、倾侧控制和采集合同，但服务器版本可能更近；不能因为旧材料提到某文件就假设服务器存在。优先使用当前已运行的代码。

### 实施顺序

按计划 Task 0–8 完成基础交付，每步做必要测试。优先形成可用的已知地图采集器，不让视觉模型或估计定位阻塞它。Task 9 估计定位和 Task 10 动作分支作为后续阶段单独报告；有依赖且基础阶段稳定时再推进。

模式必须分清：

- `known_map_gt_pose`：完整地图与真值位姿，教师/采集。
- `visible_gt_depth_gt_pose`：仅当前相机可见真值深度与真值位姿，诊断。
- `dual_mono_gt_pose`：左右 DA3 米制深度与真值位姿，首版视觉 baseline。
- `dual_mono_est_pose`：相同深度与估计位姿，后续版本。

### 编码中不能省略的事项

1. 分离 online observation 和 offline truth，视觉策略不可得到 runtime/truth 对象引用、完整地图、Oracle 路径或未来信息。用运行期 guard 测试，不只写声明。
2. 不把左右 RGB 拼接后估深。左右独立估深；batch 仅允许加在独立样本维，不静默切换多视图模型。
3. 核对当前 DA3 的输出单位与后处理。低层网络焦距缩放和高级 API 米制输出不能重复应用。模型配置、源码、权重 hash、预处理都记录。
4. 统一深度为光轴 z，明确 renderer 是 z 还是 range；图像旋转/裁剪/缩放与 K/mask 一起变换。用采集时刻姿态投影，不用完成推理时的姿态。
5. 地图保留 free/occupied/unknown。实现有可见支持的连续地面证据，既不能把未知都当自由，也不能只放稀疏点使空地无法启动。不用强制清空起点周围掩盖死锁。
6. 足迹、误差 margin、转弯和制动都要检查。未知区不盲走；不能假设球机可以原地旋转。临时子目标不是全局成功。
7. 保留并复用现有跟踪器、PID、动作协议、smoother/supervisor 和真实物理接触评分。若必须改动，单独列出原因和回归结果。
8. 先交付 lockstep 功能模式，实测并报告墙钟时长，不声称实时。若加异步，Isaac 访问留在主线程，队列有界，拒绝旧/乱序/跨 episode 深度。
9. 记录 raw/protocol/PID平滑层/applied 目标和实际关节状态；0.1 s 转移对应其后的 5 个 50 Hz 实际动作。零请求不等于物理停稳。
10. 数据先按 layout/scene family 划分，再采轨迹。原始两路 RGB 独立保存，GT 和预测深度分开。完成标记、原子写入、hash、严格 audit 和 resume 都要工作。

默认只在冻结的小规模任务上开发：先 1 条短 runtime smoke，再 E0/E1/E2 × 三基础模式的完整任务，再试采 20–30 条并审计。先不要启动大规模采集或模型训练。失败任务保留，不删除后只汇报成功。

### 工作方式

直接执行已明确的工作，不为常规文件命名、模块拆分反复询问。遇到依赖缺失，继续能独立完成的部分，并标注对应真实测试 BLOCKED；不要用 mock 冒充真实模型或 Isaac。与设计有必要偏离时，先记录偏离、原因、影响和对应检查，保持信息权限、评分与数据合同不变。

新增模块在普通 CPU 环境应可导入并运行合同/几何/记录测试，不能在 import 时启动 Isaac 或下载权重。测试关键边界行为，不以复制实现公式的测试替代几何真值和实际回放。

每个阶段留下实际命令、退出码、日志和产物位置。不要编造运行结果，不仅以“文件已生成”“无异常退出”判断导航成功。若已有错误，保存改动前证据并区分新增回归。

### 完成后交付

请输出 `reports/navigation_baseline/implementation_report.md`，至少写：

- 实际修改/新增文件，以及与交接包建议路径的映射。
- 各 mode、采集器、估计定位、动作分支分别达到什么状态。
- 已执行测试和真实仿真的命令、退出码、日志、checkpoint/commit/config hash。
- 小样本数据 manifest、audit、split 和回放产物路径。
- 已知失败与复现命令、未运行/被阻塞的项目、待解决的性能问题。
- 可直接复制执行的真实 launcher 命令。

结论要分别回答“采集链是否可用”“视觉链是否正确接通”“视觉导航效果是否达标”“是否实测实时”。不要把它们合并成一句全部完成。

完成编码后，继续使用交接包的 `prompt_verify.md` 对实际代码做独立于实现假设的验证；不因你自己写过代码就省略检查。没有条件完成的测试如实标记，保留可复查证据。
