# 球形机器人导航：服务器 AI 编码与测试交接包

日期：2026-10-16。用途：交给服务器上的 AI 实施双路单目深度导航 baseline，并利用已知地图导航采集后续学习数据。

本包是设计和验收要求，不是已经实现或运行通过的代码。它依据本地 2026-10-08 代码快照、用户提供的 2026-10-13 汇报材料和本次沟通编写；服务器现有分支可能更新，必须先核对。

## 使用顺序

1. 将整个文件夹传到服务器，放在项目仓库可访问的位置。
2. 把 `prompt_implement.md` 的全文发给编码 AI，并让它读取 `design.md` 和 `implementation_plan.md`。无需让它从零重写项目。
3. 编码 AI 完成后，把 `prompt_verify.md` 的全文发给它，或交给另一个负责验证的 AI。验证以实际 diff、运行命令、日志和产物为准。
4. 将它返回的 `environment_inventory.md`、`implementation_report.md`、`verification_report.md`、`verification_results.json`、失败记录和必要截图交回本聊天，可以继续审查。

## 文件分工

| 文件 | 内容 |
|---|---|
| `design.md` | 方法选择、信息权限、接口、建图规则、数据协议、验收定义 |
| `implementation_plan.md` | 按依赖排列的编码任务、文件职责、测试案例和交付物 |
| `prompt_implement.md` | 第一次发给服务器编码 AI 的完整提示词 |
| `prompt_verify.md` | 代码完成后发给验证 AI 的完整提示词 |

## 优先级

第一优先级是复用已知地图导航和统一记录器，产出可审计的小批量数据；第二优先级是可见真值深度与 DA3 深度共用的视觉建图规划；估计定位和同状态动作分支作为后续阶段。不要因后续阶段未完成，阻塞前面的有效交付。

## 已明确的选择

- 左右图分别估计米制深度，再融合点云或地图。
- 优先复用已有 Oracle 的规划、跟踪、倾侧控制和动作执行链。
- 真值位姿辅助的视觉版本单独标记；不得包装成完整自主定位导航。
- 原始两路 RGB 必须保留，拼接视频只是展示，不能替代训练数据。
- 本轮不训练世界模型，不引入行人跟踪，不迁移整个项目到另一套导航框架。
- 不要求安装任何特定 AI 技能。本包中的模块、命令和文件名属于拟实施接口，以服务器现状映射后为准。

## 验收结论的四种状态

`PASS` 表示执行了对应检查且满足固定条件；`FAIL` 表示执行后发现不满足；`BLOCKED` 表示缺依赖或环境导致未能执行；`NOT_RUN` 表示尚未执行。跳过、mock 通过和只生成报告均不能冒充真实 Isaac 或 GPU 验证。
