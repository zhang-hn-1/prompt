# Phase 0 研究契约：联合世界模型的数据、状态与坐标定义

## 1. 契约目的

本文档冻结球形机器人 PointGoal 联合世界模型的第一版接口。后续采集、数据加载、模型训练和 iCEM 规划都必须遵循同一语义，避免同名变量在不同模块中代表不同物理量。

机器可读版本位于：

`research/ball_wm/configs/data_contract.yaml`

本契约冻结的是正式数据管线目标。当前旧数据仍可用于原型和审计，但不因兼容旧格式而保留错误设计。

---

## 2. 最终任务

- 环境：静态室内场景；
- 任务：二维 PointGoal 导航；
- 世界模型输入：同步双目 RGB、本体状态历史、动作历史；
- 世界模型输出：未来机器人状态、未来视觉 latent、当前和未来 BEV 占据；
- 规划输入：当前 base 系相对目标坐标；
- 不生成未来 RGB；
- 不学习独立相机位姿；
- 不预测动态障碍。

PointGoal 不直接驱动环境动力学，因此不作为联合世界模型转移函数的必要输入。它在规划阶段用于评价候选 rollout 是否接近目标。

---

## 3. 时间与频率

正式采集采用：

| 子系统 | 频率 | 周期 |
|---|---:|---:|
| 物理仿真 | 50 Hz | 0.02 s |
| 状态采样 | 50 Hz | 0.02 s |
| 控制更新 | 50 Hz | 0.02 s |
| 同步双目 | 10 Hz | 0.1 s |

选择该组合的原因：

- 物理、状态和控制频率相同，控制在每个 physics step 更新；
- 视觉频率是物理频率的 1/5，每个视觉间隔固定保存 5 个状态/动作周期；
- 10 Hz 下机器人以 1.5 m/s 运动时，帧间位移约 0.15 m，时间戳仍用于精确动作窗口截取。

每个样本必须保存单调仿真时间和 physics step。禁止仅通过数组下标推断时间。

左右图像必须来自同一 physics step。仿真中要求完全同步；实物容许时间差不超过 2 ms。状态与图像的最近时间差不得超过 5 ms。

---

## 4. 动作定义

动作严格为二维：

\[
a_t=
\begin{bmatrix}
\dot q_{\mathrm{main},t}^{\mathrm{cmd}}\\
q_{\mathrm{aux},t}^{\mathrm{cmd}}
\end{bmatrix}.
\]

| 维度 | 名称 | 控制方式 | 单位 | 初始软件限幅 |
|---:|---|---|---|---:|
| 0 | 主轴关节速度命令 | velocity | rad/s | [-2.0, 2.0] |
| 1 | 副轴关节角度命令 | position | rad | [-0.28097, 0.28097] |

删除旧数据中恒为 0 的第三维。它不是机器人前进速度和转向角速度，而是直接发送给内部关节控制器的混合控制命令。

动作正值首先严格定义为仿真器关节坐标增加的方向。它对应机器人前进/后退、左转/右转中的哪一侧，必须在 Phase 1 用单关节正负阶跃实验验证后记录；不能仅依据控制函数中的变量名推断。

同时保存：

- `commanded_action`：上层控制器请求的动作；
- `applied_action`：经过限幅、延迟和底层控制后实际执行的动作。

实物没有可靠 applied feedback 时，至少保存限幅后的最终命令，并明确其不是测得的关节响应。

## 5. 动作与观测的时间语义

一条转移样本定义为：

\[
(o_t^L,o_t^R,x_t,A_{t\rightarrow t+1})
\longrightarrow
(o_{t+1}^L,o_{t+1}^R,x_{t+1}),
\]

其中 (A_{t\rightarrow t+1}) 是两个同步视觉帧之间的完整控制动作窗口，而不是单个动作。

标准采集顺序：

1. 在 physics step (n) 读取同步双目和状态 (x_t)；
2. 记录当前实际保持动作；
3. 在随后的物理步按 50 Hz 更新并记录动作；
4. 物理仿真推进，但所有 getter 禁止隐式调用 `world.step()`；
5. 在目标 physics step 读取下一组同步双目和状态 (x_{t+1})；
6. 用时间戳提取完整动作和状态窗口。

当前采集脚本中 `get_cam_pose()` 内部额外推进仿真的行为不符合本契约，必须在 Phase 1 修改。

## 6. 坐标系

### 6.1 World

固定导航世界系，用于：

- 目标世界坐标；
- base pose 真值；
- 轨迹和误差评估；
- 生成相对运动标签。

世界绝对位置和绝对 yaw 默认不进入动力学模型，避免模型依赖场景原点。

### 6.2 Base

机器人局部坐标约定：

- (+X)：机器人前方；
- (+Y)：机器人左方；
- (+Z)：机器人上方。

模型中的速度、相对运动、PointGoal 和 BEV 均使用 base 系。

### 6.3 Camera

左右相机通过固定标定外参连接到 base：

\[
T_{world}^{cam}=T_{world}^{base}T_{base}^{cam}.
\]

相机位姿不是独立学习状态。数据仍保存内参、双目外参和 base-to-camera 外参，用于双目几何与 BEV 教师生成。

### 6.4 BEV

- 原点：机器人中心；
- 图像上方：base (+X)；
- 图像左侧：base (+Y)；
- 范围：8 m × 8 m；
- 分辨率：0.1 m；
- 大小：80 × 80；
- 类别：free / occupied / unknown。

BEV 标签不做机器人尺寸膨胀；球体半径和安全裕量只在规划代价中加入。

## 7. 状态定义

### 7.1 必须保存的原始状态

- 世界系 base position；
- 世界系 base quaternion，顺序固定为 wxyz；
- 世界系 base linear velocity；
- 世界系 base angular velocity；
- 全部 3 个关节的位置；
- 全部 3 个关节的速度。

保存原始世界系数据是为了可重建和评估，不等于全部直接进入模型。

### 7.2 模型状态

统一转换为 base 系：

\[
x_t=
[v_t^{base},\omega_t^{base},g_t^{base},q_t,\dot q_t,a_{t-1}].
\]

| 分量 | 维度 | 说明 |
|---|---:|---|
| base linear velocity | 3 | m/s |
| base angular velocity | 3 | rad/s |
| gravity direction in base | 3 | 表达 roll/pitch，归一化 |
| joint position | 3 | rad |
| joint velocity | 3 | rad/s |
| previous action | 2 | 与动作 schema 一致 |
| 合计 | 17 | 第一版固定维度 |

不将以下变量作为模型状态：

- 绝对世界位置；
- 绝对世界 yaw；
- 独立相机位姿；
- 旧动作中的恒零第三维。

## 8. PointGoal 表达

目标首先在 world 系给出：

\[
p_g^{world}=[x_g,y_g].
\]

每次规划时转换成当前 base 系：

\[
g_t^{base}
=R_{world\rightarrow base,t}
(p_g^{world}-p_t^{world})
=
\begin{bmatrix}
\Delta x_{forward}\\
\Delta y_{left}
\end{bmatrix}.
\]

- (\Delta x>0)：目标在前方；
- (\Delta x<0)：目标在后方；
- (\Delta y>0)：目标在左侧；
- (\Delta y<0)：目标在右侧。

模型和规划器使用米制二维笛卡尔坐标，不使用目标图像。距离和方位角只作为代价或日志派生量。

---

## 9. 视觉、状态与动作窗口

第一版历史和预测范围：

- 历史时长：0.5 s；
- 历史双目帧：5；
- 历史状态样本：25；
- 历史动作样本：25；
- 初始预测时长：1.0 s；
- 未来视觉/BEV 步：10。

不同频率数据不通过重复图像强行变成 50 Hz。状态和动作分别编码后，通过时间位置编码与视觉 token 在联合 Transformer 中融合。

---

## 10. 数据划分

- 按场景和 episode 划分；
- 训练/验证/测试比例为 70%/15%/15%；
- 同一 episode 不跨 split；
- 禁止相邻帧随机划分；
- 测试集必须包含未见场景；
- 额外保留高转向、制动和动作扰动的分布外测试集。

---

## 11. 训练期与部署期输入边界

训练期允许使用：

- 仿真深度或点云；
- BEV 真值；
- 世界 pose 真值；
- 碰撞标签。

部署期只允许使用：

- 同步双目 RGB；
- 本体状态历史；
- 动作历史；
- 规划器所需的相对 PointGoal。

深度、BEV 真值和世界 pose 真值不得作为完整模型部署时的隐藏输入。
