# 球形机器人双向运动学 Oracle 与任务认证设计

## 1. 背景与问题

Ball PointGoal Benchmark V1 当前使用二维占据图上的 A* 路径作为 Oracle 参考，再由固定前视距离的
几何控制器直接把航向误差映射为副轴角度。联合动力学标定证明这种映射不成立：副轴具有约
`0.76–0.90 s` 的回正延迟和约 `3.2°–4.0°` 的反向回弹，相同副轴角度在不同主轴速度下产生的
曲率也不同，制动距离随速度明显非线性。

冻结 `hard_0` dev 任务上的诊断进一步表明，普通 A* 没有描述机器人朝向和最小转弯半径：

- `hard_0_e1_0002` 的初始 yaw 与 A* 首段相差约 `59°`；
- `hard_0_e1_0004` 的初始 yaw 与 A* 首段相差约 `125°`；
- 两个任务中副轴从开始到终止始终饱和在 `±30°`；
- 其余 E1 任务也有约 `41%–70%` 的控制时间处于副轴饱和状态。

因此，普通 A* 只能证明球心在几何上存在一条栅格通路，不能证明带朝向、转向迟滞和制动距离的
球形机器人能够执行该任务。Benchmark 需要一个尊重机器人动力学的特权 Oracle，用它认证任务，
而不是通过修改起始 yaw 掩盖问题。

## 2. 目标与非目标

### 2.1 目标

1. 实测负主轴速度下的转向响应，形成前进/后退完整的紧凑动力学配置。
2. 使用包含 `(x, y, yaw, drive_direction)` 的双向 Hybrid A*/状态格规划器生成可执行参考轨迹。
3. 使用速度相关前视、标定转角前馈、yaw-rate 反馈、换向停车和提前制动完成闭环跟踪。
4. 在不修改现有 `hard_0` 起点、终点和初始 yaw 的前提下，重新认证全部 7 个 dev 任务。
5. 将几何可达与动力学可执行明确分开，并为每个任务保存失败原因和可视化证据。

### 2.2 非目标

- 不修改用户已经确认的主轴与副轴 PID 参数、动作平滑限制或 `±30°` 关节边界。
- 不改变正式无地图策略的在线输入，不把占据图、Hybrid A* 路径或候选原语提供给学习策略。
- 不在本阶段训练世界模型、风险头、价值头或行为策略。
- 不承诺通过放宽碰撞、goal tolerance 或 episode 时间预算提高成功率。
- 不就地修改已冻结 manifest；需要替换任务时发布新 manifest 版本并保留旧结果。

## 3. 方案选择

### 3.1 采用方案：标定驱动的双向 Hybrid A*

规划器在离散位置、离散 yaw 和驱动方向状态上搜索。每条边由固定时间的主轴速度与副轴角度生成，
曲率来自实测动力学配置。它能在起始朝向不利时选择倒车、前进或换向组合，并在生成路径时直接
拒绝超出最小转弯半径或穿过膨胀障碍的动作。

该方案比“先 A* 再平滑”更适合当前问题，因为后者可能在狭窄转角处无法找到任何满足曲率约束的
平滑曲线；也比直接为四个 E1 手调控制序列更可复现，并能用于后续新场景的自动认证。

### 3.2 未采用方案

- **修改初始 yaw：** 实现最简单，但会删除起步恢复能力这一真实难点，且需要改变冻结任务。
- **只增加 Pure Pursuit 前视距离：** 已在 7 个任务上验证，成功率仍为 `3/7`，并使 E0 变慢。
- **连续非线性 MPC：** 表达能力强，但当前标定数据量不足以稳定识别连续动力学，调试和依赖成本
  高于 V1 基准所需。Hybrid A* 输出可作为未来 MPC 的安全参考。

## 4. 反向动力学标定

现有标定包含正向转弯和正反向直行，但没有负主轴速度下的转弯。实施前必须增加以下工况：

- 主轴 `-0.5/-1.0/-1.5 rad/s`；
- 副轴 `-30/-20/-10/+10/+20/+30°`；
- 每个工况记录实际主轴速度、实际副轴角度、平面速度、yaw rate、曲率和转弯半径；
- 增加倒车制动 `-0.5/-1.0/-1.5 rad/s`；
- 保持当前 `0.5 rad/s²` 主轴加速度限制、`30°/s` 副轴目标速率和现有 PID。

原始 trace 继续保存在忽略 Git 的 runs 目录。生产代码只使用从完整报告导出的紧凑版本化配置，
其中包含测量日期、动作协议、PID、速度—曲率表和速度—制动距离表。配置不得手工填写未经测量的
反向曲率。

## 5. 双向 Hybrid A* 规划器

### 5.1 状态和运动原语

搜索状态为 `(row, column, yaw_bin, drive_direction)`：

- 空间栅格沿用冻结占据图的 `0.1 m` 分辨率；
- yaw 使用 72 个离散方向，即每格 `5°`；
- `drive_direction` 为 `forward` 或 `reverse`，等价于该原语主轴命令的正负号，不代表机械挡位，
  也不增加新的控制量、传感器量或世界模型预测量；
- 原语主轴命令为 `±0.5`、`±1.0`、`±1.5 rad/s`；
- 原语副轴角为 `-30/-20/-10/0/+10/+20/+30°`；
- 每条原语按紧凑标定表得到曲率，并沿圆弧以不大于 `0.05 m` 的间距检查碰撞；
- 规划碰撞图继续使用 `ball_radius=0.4 m + safety_margin=0.1 m` 的膨胀半径。

第一版原语的目标弧长固定为 `0.3 m`。搜索代价为实际弧长，并加入倒车倍率 `1.25` 和换挡等价
代价 `0.5 m`。启发函数使用到目标的欧氏距离，不高估基础路程。每次搜索最多扩展 250,000 个
节点；目标位置误差不超过 `0.2 m` 且终点 yaw 不受约束。

### 5.2 参考路径与 SPL

Hybrid A* 输出带位姿、驱动方向和前馈动作的可执行参考轨迹，仅供 `privileged=true` 的 Oracle 使用。
Benchmark 中原有无朝向约束的最短栅格 A* 长度仍作为 SPL 分母，避免动力学 Oracle 因使用更长
路径而人为获得更高 SPL。审核图同时显示：

- 蓝色：原始最短栅格 A*；
- 紫色：Hybrid A* 动力学参考；
- 橙色：机器人实际轨迹。

Isaac runtime 在读取冻结占据图并完成原始 A* 后调用 Hybrid A*，再通过扩展后的特权
`EpisodeContext` 把不可变的位姿、驱动方向和前馈动作序列交给 Oracle。核心 `PolicyObservation` 不增加
任何地图或参考路径字段，非特权策略仍无法获得这些信息。

## 6. 闭环跟踪与换向

Oracle 每个 10 Hz 重规划周期执行以下逻辑：

1. 将当前位置投影到动力学参考轨迹，索引只能单调前进；
2. 根据实际平面速度选择 `0.45–0.9 m` 前视距离；
3. 从轨迹目标计算期望曲率，并由对应驱动方向和速度的标定表得到副轴前馈；
4. 使用本体状态中的实际 yaw rate 做有限幅反馈修正；
5. 根据即将到来的曲率降低主轴目标，根据标定制动距离提前制动；
6. 到达方向切换点时先命令主轴为零；实际平面速度连续 5 个 10 Hz 周期低于 `0.05 m/s` 后再反转主轴命令符号；
7. 使用滞回避免在相邻周期频繁前进/后退切换。

所有输出仍经过统一 `ActionSmoother`，所以规划器不能绕过主轴加速度或副轴目标速率限制。若机器
人到动力学参考轨迹的最近距离连续 10 个重规划周期大于 `1.0 m`，Oracle 输出安全停车。Runner
仍将 episode 记为 `timeout`，同时在审核包中增加 `failure_subreason=tracking_infeasible`，不扩展 V1
既有的四种顶层终止原因。

## 7. 任务认证协议

认证分为三层：

1. **几何检查：** 原有膨胀图 A* 存在，起终点和哈希有效；
2. **运动学检查：** Hybrid A* 在固定节点预算内找到无碰撞轨迹；
3. **物理检查：** Isaac Sim 闭环运行成功，且没有 `collision` 或 `runtime_error`。

当前 7 个 `hard_0` dev 任务保持不变先执行认证。通过门槛为：

- E0 `3/3` 成功；
- E1 `4/4` 成功；
- 总碰撞率 `0`；
- 每个 episode 在现有 20 秒预算内结束；
- 轨迹、动作、最小 clearance、第三人称视频和双目视频均完整保存；
- 人工审核确认机器人确实绕过障碍，而非利用判定漏洞或偶然穿模。

若某任务通过运动学检查但物理检查失败，先记录跟踪误差并修正统一控制器。若扩展 250,000 个
节点后仍不存在运动学路径，则将其标记为 `kinematically_infeasible`；只有此时才提出新 manifest 版本，
不得静默修改当前任务的起点、终点或 yaw。

## 8. 公平性边界

Hybrid A*、完整地图和动力学参考都是 Oracle 的特权信息。`drive_direction` 只保存在规划器内部和
特权参考轨迹中；执行接口仍只有 `main_joint_velocity_cmd` 与 `auxiliary_joint_angle_cmd`。它们的用途是：

- 证明任务对该球形机器人可执行；
- 提供路径长度和控制性能上界；
- 生成高质量专家轨迹，供后续离线训练使用时明确标记为 expert 数据。

正式视觉策略仍只能使用双目 RGB、本体历史、完美定位、base-frame PointGoal 和动作历史。未来用
Oracle 轨迹训练策略时，地图和参考路径只能用于生成监督标签，不能成为部署时输入。

## 9. 文件边界

- `research/ball_wm/scripts/probe_drive_dynamics.py`：增加反向转弯与反向制动标定。
- `research/ball_wm/configs/benchmark_v1/drive_dynamics_v1.json`：紧凑、版本化标定配置。
- `research/ball_wm/benchmark/drive_model.py`：读取配置并提供曲率、制动距离插值。
- `research/ball_wm/benchmark/kinodynamic_planning.py`：纯 NumPy Hybrid A* 与运动原语碰撞检查。
- `research/ball_wm/benchmark/policies.py`：Oracle 跟踪、换挡和诊断状态。
- `research/ball_wm/benchmark/isaac_runtime.py`：接收并绘制动力学参考，不改变正式 observation。
- `research/ball_wm/scripts/run_pointgoal_benchmark.py`：保存认证状态和新增轨迹层。
- 对应 `research/ball_wm/tests/`：全部纯计算行为先写失败测试，Isaac 只做最终物理验收。

## 10. 测试与交付

实施遵循测试驱动开发：

1. 先验证反向标定矩阵和紧凑配置导出；
2. 再验证前进/后退曲率插值、制动插值和符号；
3. 用人工构造的小栅格验证 Hybrid A* 的直行、绕障、倒车起步、碰撞检查和不可达退出；
4. 验证换挡必须先停车、轨迹索引单调、输出满足动作协议；
5. 运行 benchmark/runner/artifact 回归测试；
6. 在冻结 7 个任务上执行 headless 评测并生成完整审核包；
7. 至少选择一个 E1 在 GUI 中复现，供项目负责人检查路径、动作和实际运动是否一致。

第一版曲率跟踪实验 `benchmark_hard_0_oracle_curvature_v1` 保留为失败对照，不纳入正式 Oracle
上界。只有达到第 7 节的认证门槛，双向运动学 Oracle 才能替换当前 Oracle 基线。
