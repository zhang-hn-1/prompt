# 球形机器人动态状态格规划器 V2 设计

## 1. 背景与目标

当前 Oracle 使用双向 Hybrid A* 生成几何与稳态曲率可行的参考轨迹，再由纯追踪控制器执行。`hard_0_e1_0002` 的逐步诊断表明，规划参考允许副轴命令在相邻路点间从 `+30°` 切换到 `-30°`，但真实控制器的副轴目标变化速度只有 `30°/s`。规划器没有表示这个执行延迟，导致机器人切弯并碰撞。

规划器 V2 的目标是生成在现有球形机器人控制器上可执行的局部 Oracle 轨迹，并作为后续学习方法的可靠上界与数据来源。

本设计不引入全局地图作为学习策略的在线输入。Oracle 仍是 Benchmark 中的特权基线；非特权策略继续只接收双目 RGB、本体状态、动作历史、完美位置/yaw 和 PointGoal。

## 2. 核心原则

V2 采用“离散候选动作、连续动力学传播、量化状态去重”的混合方式：

- 搜索只枚举有限的控制目标，保证搜索规模可控；
- 每个运动原语内部以连续值模拟主轴命令、副轴实际角度、速度、位置和 yaw；
- 连续传播结果只在加入搜索闭集时量化；
- 输出给执行器的是带时间的连续参考，而不是要求机器人瞬间跳到某个离散状态。

动作协议保持 `ball_action_v2_aux30`，实际输出范围仍为主轴 `[-2, 2] rad/s`、副轴 `[-30°, 30°]`。

## 3. 方案选择

### 3.1 采用：在线动态状态格搜索

动态状态格直接使用当前标定模型传播运动原语，搜索状态包含执行器状态。它不需要新的学习模型，结果可解释，并能对每条路径给出碰撞、时间和控制代价。

### 3.2 暂不采用：几何路径后的连续轨迹优化

该方案计算速度较快，但优化器可能在狭窄区域无法把几何路径修正为动力学可行轨迹，且失败原因不如状态格明确。后续可作为 V2 的路径平滑器，但不作为首个可靠 Oracle。

### 3.3 暂不采用：Isaac Sim 离线原语库

直接用仿真采集每个控制切换的轨迹最接近真实动力学，但需要覆盖大量初始速度、转角和动作组合。现阶段先使用已经验收的动力学标定模型；若 V2 仍有稳定系统误差，再补充离线原语库。

## 4. 状态、动作和时间

### 4.1 连续传播状态

每个搜索节点保存：

```text
(x_m, y_m, yaw_rad,
 main_command_rad_s,
 auxiliary_angle_rad,
 speed_m_s,
 elapsed_s,
 drive_direction)
```

其中 `main_command_rad_s` 和 `auxiliary_angle_rad` 表示控制器当前已经达到的连续状态，不是下一步目标。

### 4.2 搜索键量化

闭集键使用：

```text
(occupancy_row, occupancy_col,
 yaw_bin,
 main_command_bin,
 auxiliary_angle_bin,
 speed_bin,
 drive_direction)
```

- 位置分辨率使用冻结的 occupancy resolution `0.1 m`；
- yaw 使用现有的 72 个方向箱，即每箱 `5°`；
- 主轴命令按 `0.25 rad/s` 量化；
- 副轴角度按 `5°` 量化；
- 速度按 `0.05 m/s` 量化；
- 连续状态本身不被量化值覆盖。

速度必须加入闭集键：即使位置、yaw 和执行器命令相同，不同实际速度也具有不同的制动距离，不能互相覆盖。

### 4.3 候选控制目标

主轴候选目标：

```text
-1.5, -1.0, -0.5, 0.0, 0.5, 1.0, 1.5 rad/s
```

副轴候选目标：

```text
-30°, -20°, -10°, 0°, 10°, 20°, 30°
```

候选值只用于产生分支。传播过程中按照速率限制连续逼近目标。

为控制分支数量，每个节点只产生一个原语时长内物理可达的目标：主轴目标相对当前量化值最多变化 `0.5 rad/s`，副轴目标相对当前量化值最多变化 `30°`。超出协议边界的目标直接删除。

### 4.4 运动原语时长

每个规划原语持续 `1.0 s`，内部以 `0.02 s` 步长传播，共 50 个子步，与 Isaac Sim 的 `50 Hz` physics schedule 对齐。

每个子步执行：

1. 主轴当前命令以最大 `0.5 rad/s²` 逼近目标；
2. 副轴当前角度以最大 `30°/s` 逼近目标；
3. 从 `DriveModel` 插值得到当前速度和曲率；
4. 连续积分 `(x, y, yaw)`；
5. 在 occupancy 上检查轨迹中心是否进入膨胀障碍物。

任何一个子步碰撞，整个原语无效。

`DriveModel` 需要增加连续主轴命令下的稳态速度插值。传播时先按主轴加速度限制更新连续主轴命令，再由更新后的命令插值得到速度；接近零速和方向切换时，使用现有制动样本的 `stop_time_s` 与 `stopping_distance_m` 作为保守下界，传播距离不得短于标定制动距离。V2 第一版不声称建模轮胎滑移等未标定的瞬态；这些误差由仿真门槛检验，不能通过放宽碰撞标准掩盖。

规划在 runtime reset 之后执行，初始主轴命令、副轴角度和速度直接读取 reset observation，不能假设全部为零。目标节点除距离目标不超过 `0.2 m` 外，还必须满足速度小于 `0.05 m/s`、主轴命令绝对值不超过 `0.05 rad/s`。

## 5. 正反向切换

主轴不能从正值直接跳到负值，反之亦然。合法切换必须经过 `0 rad/s` 原语。

只有满足以下条件后才允许产生相反方向的非零候选：

- 当前主轴命令的绝对值不超过 `0.05 rad/s`；
- 当前估计速度小于 `0.05 m/s`；
- 已连续停稳至少 `0.5 s`。

这与现有执行控制器的五个 `10 Hz` 停稳周期保持一致。

## 6. 代价函数与启发式

累计代价由以下项目组成：

```text
J = 行驶距离
  + 时间代价
  + 倒车代价
  + 换向代价
  + 控制变化代价
  + 低间距风险代价
```

- 行驶距离保持路径效率；
- 时间代价避免安全但极慢的轨迹；
- 倒车和换向代价沿用 V1 的偏好；
- 控制变化代价惩罚频繁改变主轴目标和副轴目标；
- 低间距风险代价使用 occupancy 距离场，在不改变 Benchmark `0.1 m` 安全标准的情况下，优先选择更易跟踪的轨迹。

V2 初始权重冻结为：基础距离 `1.0`、时间 `0.05 m/s`、倒车距离倍率 `1.25`、换向 `0.5 m`、主轴目标变化 `0.10 m/(rad/s)`、副轴目标变化 `0.10 m/30°`。低间距风险在每个 `0.02 s` 子步增加 `0.02 / (d + 0.05) × 0.02 m`，其中 `d` 是机器人中心到膨胀障碍边界的距离，单位为米。风险项只影响排序，不改变碰撞边界。

启发式继续使用障碍物感知的二维 cost-to-go。启发式不得加入控制变化和风险惩罚，以保持其不高估基础到达代价。

默认搜索节点预算为 `500,000`，单任务墙钟规划上限为 `60 s`。规划时间不计入 35 秒执行预算，但必须写入审计指标。预测轨迹时长超过 `32 s` 的目标节点不予接受，为末端停稳和仿真调度保留至少 3 秒。

## 7. 输出接口

V2 新增独立的数据结构，不覆盖 V1：

```python
@dataclass(frozen=True)
class DynamicWaypoint:
    time_from_start_s: float
    x_m: float
    y_m: float
    yaw_rad: float
    speed_m_s: float
    main_command_rad_s: float
    auxiliary_angle_rad: float
    drive_direction: str

@dataclass(frozen=True)
class DynamicPlanResult:
    status: str
    waypoints: tuple[DynamicWaypoint, ...]
    expanded_nodes: int
    path_length_m: float
    duration_s: float
    direction_changes: int
```

V1 的 `KinodynamicPlanResult` 保留，用于结果对照和回归测试。

## 8. 跟踪控制器

V2 使用前馈加反馈控制：

- 前馈项来自当前时间对应的 `main_command_rad_s` 和 `auxiliary_angle_rad`；
- 反馈项根据机器人与参考点的位置横向误差和 yaw 误差小幅修正副轴目标；
- 主轴根据横向误差、yaw 误差和副轴未到位程度连续降速；
- 所有输出仍经过现有 `ActionSmoother`，不能绕过主轴加速度或副轴速率限制；
- 方向切换继续执行实际速度停稳检查。

控制器不能读取 occupancy、truth clearance 或碰撞标签。地图只在特权规划阶段使用，避免把在线安全真值泄漏给跟踪器。

## 9. 文件边界

- 新建 `benchmark/dynamic_lattice_planning.py`：状态、传播、碰撞检查和搜索；
- 在 `benchmark/policies.py` 中加入 `DynamicOraclePolicy`：带时间参考跟踪；
- 修改 `benchmark/isaac_runtime.py`：为 V2 提供起始执行器状态和动态计划缓存；
- 修改 `scripts/run_pointgoal_benchmark.py`：增加明确的 `oracle_v2` 策略选项和 V2 审计数组；
- 修改 `benchmark/artifacts.py`：校验 V2 时间参考和执行诊断；
- V1 的 `oracle` 名称和历史产物语义保持不变。

## 10. 失败处理

规划结果必须区分：

- 起点或终点无效；
- 地图不可达；
- 动态状态搜索预算耗尽；
- 找到几何路径但没有动态可行路径；
- 输出参考时间或控制状态不连续。

规划失败不能退化为直线行驶或 GoalGreedy。Benchmark 必须记录 `runtime_error` 或明确的规划失败原因。

## 11. 测试与验收

### 11.1 纯代码测试

- 主轴连续传播每秒变化不超过 `0.5 rad/s`；
- 副轴连续传播每秒变化不超过 `30°`；
- 正负主轴切换必须经过停稳状态；
- 子步中任意碰撞都会拒绝整个原语；
- 搜索结果确定性可复现；
- 输出时间严格递增，状态和命令均为有限值；
- 跟踪器不具备 occupancy 或 truth clearance 在线输入权限；
- V1 测试继续全部通过。

### 11.2 分阶段仿真门槛

第一门槛只运行 `hard_0_e1_0002`：

- 35 秒内成功；
- 无碰撞；
- 最大横向误差小于 `0.2 m`；
- 动态参考不存在超过主轴或副轴速率限制的跳变。

通过后运行 7 张冻结任务卡：

- 成功率至少 `6/7`；
- 碰撞不超过 `1/7`；
- 当前 V1 已成功的四项不得退化为碰撞或超时；
- 继续使用 `ball_pointgoal_v1_1_35s`、`0.1 m` safety margin 和冻结 manifest；
- 每项保存轨迹图、第三视角视频、双目视频、动态参考和逐步执行诊断。

未通过第一门槛时不运行全套评测，先依据审计数据修正模型或控制接口。

## 12. 范围外内容

本阶段不实现：

- 世界模型训练；
- 风险头；
- 长期记忆或全局学习地图；
- 真机数据采集；
- 在线读取真实障碍物地图的非特权策略；
- 为提高数字而修改冻结任务、碰撞阈值或 35 秒预算。
