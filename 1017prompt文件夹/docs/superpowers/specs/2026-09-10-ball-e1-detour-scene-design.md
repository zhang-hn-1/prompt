# 球形机器人 E1 单侧绕障场景设计

## 1. 目的

新增一个可复现、可人工审查的 E1 PointGoal 场景，用来验证机器人是否真正完成了“前方障碍阻断后的局部绕行”，而不是仅在开放区域或直通通道中向目标前进。

该场景必须通过现有的 `${SCENE_ROOT}` 外部场景接口、场景索引、冻结 body-band 占据图、A* Oracle、任务卡和审计视频加载。不得为该场景添加任何运行时特例。

## 2. 非目标

- 不修改世界模型、CEM、风险头或无地图学习策略。
- 不把 Oracle 的真值地图提供给核心公平赛道方法。
- 不将此单一场景的成功率解释为完整 Benchmark 成功率。
- 不在本次改动中永久修复 E2 场景的 USD 属性类型错误；E2 修复与其冻结资产重生成应单独完成。

## 3. 场景资产与加载方式

### 3.1 标准资产

新场景名为 `e1_detour`，采用标准 USDA：

- 版本受控资产：`research/ball_wm/data/benchmark_v1/scenes/e1_detour.usda`；
- 运行时场景：`${SCENE_ROOT}/benchmark_e1/e1_detour.usda`；
- 场景索引 URI：`${SCENE_ROOT}/benchmark_e1/e1_detour.usda`。

版本受控资产与运行时副本必须字节一致，场景 SHA256 写入场景索引、冻结占据图和 Manifest。运行时通过既有 `scene_root` 参数解析 URI，不改变 `IsaacBenchmarkRuntime` 的场景加载逻辑。

### 3.2 USD 约束

场景只使用竖直 `UsdGeom.Cylinder` 和 `PhysicsCollisionAPI`。所有模式属性必须使用 USD 规范类型：

```usda
double radius = 0.35
double height = 1.0
```

禁止使用 `float radius` 或 `float height`。前者会使 PhysX 可能回退到 Cylinder/Sphere 的默认尺寸，导致可视几何、碰撞几何和冻结占据图不一致。

## 4. 几何设计

场景是一个由圆柱围成的平面测试区。圆柱高度为 `1.0 m`、中心高度为 `z=0.5 m`、半径为 `0.35 m`。相邻围栏圆柱的中心间隔为 `0.6 m`，保证原始障碍物连通。

| 元素 | 位置/范围 | 作用 |
| --- | --- | --- |
| 外围栏 | `x=±4.8 m`、`y=±4.5 m`，用连通圆柱形成封闭边界 | 防止机器人从场景边缘绕开测试障碍 |
| 中央分隔墙 | `x=0 m`，`y=-1.8 m` 至 `4.2 m` | 阻断起点到终点的直线，并与上围栏连通 |
| 下方绕行口 | 中央墙下端与下围栏之间 | 唯一的短可行绕行区域 |
| 起点 | `(-3.3, 0.0, 0.45)` | 面向 `+x` |
| 终点 | `(3.3, 0.0, 0.45)` | PointGoal 目标 |

球形机器人半径为 `0.4 m`，安全裕度为 `0.1 m`。中央墙最下端的原始表面约为 `y=-2.15 m`，下围栏最上侧原始表面约为 `y=-4.15 m`，原始通路宽度约为 `2.0 m`。以 `0.5 m` 进行障碍膨胀后，规划中心仍约有 `1.0 m` 的可通行宽度。

起终点欧氏距离为 `6.6 m`。最短可行路径必须下绕中央墙，理论绕行率约为 `1.38`，高于 E1 的固定阈值 `1.3`。上侧绕行被中央墙与上围栏的连通结构阻断；外部围栏使其不能从地图边缘逃逸。

## 5. Benchmark 接入

在既有 `scene_index.json` 新增一条记录：

- `scene_id: e1_detour`；
- `difficulties: ["E1"]`；
- body-band 资产 URI、场景 URI、场景/占据图 SHA256、球半径和导航高度与当前其他场景一致。

使用既有 `generate_benchmark_tasks.py export-scene` 生成冻结体高度带占据图。随后以固定起终点生成候选任务并渲染任务卡。候选必须通过现有 E1 校验：直线不可通、A* 存在、绕行率不低于 `1.3`、端点 clearance 合格、附近障碍数量合格。

审核通过后，将该任务冻结为 Golden E1 任务；后续可在同一场景中采样 Dev 任务，但不得替换已冻结 Golden 任务。

## 6. 验收与审计

资产、任务和控制器按以下顺序验收：

1. 静态资产检查：版本受控和运行时副本 SHA256 相同；所有 radius/height 均为 `double`。
2. 地图检查：冻结占据图阻断直线；膨胀图中存在且仅存在下方的短绕行路径。
3. 任务卡检查：显示原始障碍、膨胀区、起点、目标和 A* 绕行路径；人工审核场景与地图对应关系。
4. 运行检查：Oracle 在 20 秒预算内无碰撞成功，并保存第三人称视频、双目视频、轨迹叠加图、状态和动作。
5. 对照检查：同一冻结任务上的 `goal_greedy` 不得被描述为避障成功；它应碰撞、超时或在 Success/SPL 上显著低于 Oracle。

正式结果需要同时报告 Success、SPL、Collision、Timeout、路径长度、最小 clearance 及终止原因。单条 Golden 轨迹仅是链路验收，不得代替批量成功率。

## 7. 实施边界

本次只新增 E1 控制场景和相应冻结资产/任务记录。`cluttered_easy` 仍保留为后续复杂真实场景评测对象；新 E1 的任务审查方法将用于筛选其中的绕障任务，但不会修改它的场景文件。
