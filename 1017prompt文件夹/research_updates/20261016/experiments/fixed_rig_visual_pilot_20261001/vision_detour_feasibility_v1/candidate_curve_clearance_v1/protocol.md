# Candidate-curve clearance label feasibility audit V1

Purpose: test whether existing full RGB/depth episodes support a route-level clearance baseline, before fitting another network. This is an offline **label and observability audit** only; it does not change navigation actions or claim new success rates.

Use the fixed camera pose and current measured root XY/quaternion at each saved frame. Generate exactly three local 4.0m candidate center paths in the instantaneous body forward/right frame: straight, left, right. Sample forward distance x=0..4m every 0.1m. For left/right, lateral offset magnitude is `2.3 * smoothstep(min(x/3.0,1))` metres. Do not read future actions, future poses or episode ID in the candidate geometry. For offline labels only, use the correct scene's frozen body-band occupancy map; world map axis 0 is X and axis 1 is Y. A candidate is `blocked` if any sampled center point has less than 0.60m clearance from a **known occupied cell**, `unknown` if it leaves the map before any known block, and `clear` otherwise. The map edge is unknown, not an invented obstacle. These are geometric labels, not physical-contact verdicts or RGB observations.

Fit-side episode inventory: complete E0/E1/E2 direct and hard_0 E1 0001/0002 sequences. Test-side inventory: complete hard_0 E1 0003/0004, already inspected in prior work and therefore **not fresh held-out**. Keep whole episodes separate; never random-split frames. The first gate is dataset viability, not model accuracy: at least 15 fit-side frames and 5 frames in each test episode must present both a clear and a blocked candidate; otherwise no classifier is trained from this set. Also report each candidate's class counts and how often all three candidates are blocked or unknown. A map-safe curve may still be unseen in RGB, so no map label alone certifies visual observability.
