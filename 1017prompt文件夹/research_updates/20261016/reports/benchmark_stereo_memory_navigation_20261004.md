# 固定双目、空间记忆与采集接口：2026-10-04阶段研究记录

本阶段已经实际执行双目推理、开放平面观察、导航诊断及采集消融。**完整双目记忆导航与世界模型研究尚未完成。** 当前结果不能称作完成的纯视觉导航基线，也没有新增正式E0/E1/E2成功率。

## 1. 本阶段解决和发现了什么

1. 接通真正使用两幅RGB匹配的双目深度：一个固定SGBM配置及一个冻结官方Fast-FoundationStereo，分别完成原采集66对与仅渲染修正66对。没有以单目网络输出冒充双目。
2. 核验实际相机极线和标定。相机位置未改，原生图像的极线为垂直方向；逆时针90°旋转后成为横向极线，左右顺序保持测得顺序。已知静态平面的重投影可以达到约2.35×10⁻⁷m误差。
3. 发现“时间戳是当前”不等于“内容和当前位姿一致”。静态排队、移动时位姿与渲染内容的错位分别得到实测证据。仅三次渲染和单独提前刷新FK均未改善已测导航；需完成单次基础capture后的图像事务。
4. 新空间记忆保存观测时间与未知状态；支持检查包含实测停止尾迹。但是这些原型还没有接入本阶段风险导航，不能把它们的单元测试说成导航成功。
5. 独立审查发现实际风险导航继承旧地图的滚动0.4m足迹先验。协议中`unknown_labels_unchanged:true`被实际代码和快照否定。旧协议、源码和成绩保留，另行记录限制，不追改旧结果。

## 2. 相机、数据和方法身份

相机固定为`ball_stereo_front020_up005_v2`，相对base_link：前向X=0.20m，左右Y=±0.30m，向上Z=0.05m；640×480。基线0.60m，焦距约584.8889px。双眼机体遮挡mask冻结，单眼mask比例约46.24%；沿用固定照明。没有变更机器人相机的实际安装。

原开发数据由e0、e1、e2、hard_0_e1_0003、hard_0_e1_0004、direct_e1六条完整轨迹选取66对。仅渲染修正数据重跑同一请求序列、相同选定索引；六条选定物理状态与原数据差精确为0。两版都已经参与分析，**均不是新的held-out**。

双目预测器只读取左右RGB和冻结mask；renderer深度与位姿仅用于离线标签。SGBM固定448视差、block5、3WAY及双向一致性1.5px，没有扫描参数。Fast使用[官方项目](https://github.com/NVlabs/Fast-FoundationStereo)冻结源码commit `476f4249561f7c79ca707326954f9255643412a6`，官方23-36-37权重；SHA256为`af0658f289ec840b292645f8d5538978f06e8cabaa1fd31e84acc91af268e990`。运行8次迭代、官方416视差、双向匹配及mask检查，没有拟合。

普通pickle权重加载被自动审批拒绝后，采用静态GLOBAL审计、精确权重哈希、经审查类的allowlist以及`weights_only=True`成功执行。没有通过关闭安全加载绕过拒绝。原SGBM与原Fast审计入口均已补存与运行记录SHA精确一致的归档文件。

## 5. 空间记忆和局部运动原型的完成范围

SpatialMemory保留当前地面、历史地面、障碍和未知；地面观测最长10秒，位姿不确定度超过0.05m不增加地面可信度，障碍覆盖地面，过去查询不能读取未来记录。它是2.5D地面/障碍记忆，尚不是全3D碰撞体积证书。

primitive_planner检查实测运动与停止尾迹覆盖的支持圆盘，未知或障碍拒绝，明确`full_3d_certified=False`。它目前是离线检查原型，**并未被实际导航消费者调用**。

实际风险导航仍用继承的InformationPolicy、旧grid A*、几何tracker、方向锁存和roll PID。继承地图每帧seed_body会把滚动0.4m圆盘内未观测区域写成自由，没有来源标签；初始快照有49格来自这个先验。新SpatialMemory没有这个写入行为，但没有替换到风险arm。因此不能把实际导航的known_free增长全部算作视觉记忆增益。

## 6. 采集接口：静态、移动和调用位置分开验证

### 静态排队

物理时间和相机位姿不变时，第一次地面深度与下一次深度最大相差44.58m；地面重投影中值z从0.01166m到约2.31×10⁻⁷m。新增独立非碰撞标定板后第一次仍看到旧地面，后续才看到2m板。三次固定普通渲染可消除已测静态队列，不读取深度来决定何时停止。

![同物理时间的静态内容排队](/home/an/Documents/ChatGPT/球型机器人导航/experiments/stereo_memory_navigation_20261004_v1/figures/static_queued_geometry.png)

### 移动错位

一条固定12秒前进停止探针，缓存与直接annotator读取完全相同；三次渲染后，部分帧按当前位姿投影地面仍偏离，采用前0.1秒物理位姿时误差约10⁻⁷m。这里过去位姿只用于离线诊断，未作为模型未来输入或在线补偿。

第二条探针在基础capture后额外执行三次带FK刷新的渲染，当前位姿一致性恢复。独立审查用共同有效像素和几何向下射线、不按地面误差筛点，9时刻×双眼18组p90最大4.07×10⁻⁷m。0.4秒左目从0.1576m降到约2.38×10⁻⁷m。所有19项物理数组与原前进序列逐项完全相同。

**但不能单独归因于FK。** 第二条同时增加渲染次数和改变调用位置；仅把FK放在基础capture前的实际导航，图像、动作和物理状态都没有改善。

第三条12秒消融冻结顺序：三次普通渲染A → 单次基础capture → 三次额外普通渲染B → 三次FK渲染C。B已恢复同像素地面一致性，18组p90最大4.07×10⁻⁷m；C不再带来改善。它反证FK是必要因素的说法，支持完成基础capture后的图像事务。基础capture还会写USD轨迹属性，调用位置与累计渲染的更细机制未完全拆开。

当前受控修复完成一次基础capture后，再固定三次普通渲染，替换其RGB和视频帧；不二次调用capture、policy，不重复更新状态历史，也不多走物理时间。旧数据、FK候选和失败导航保持冻结。该修复的全场景导航迁移验收必须看实际重跑，不能用开放平面一致性代替。
